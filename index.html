Procesos y planificación de procesos

Un taller para estudiantes que están empezando. Se trabaja con sintaxis sencilla, ejemplos visuales y el mismo objeto Proceso en Java y Python para entender qué hace cada algoritmo sin distraerse con estructuras avanzadas.

1. Repaso: ¿qué es un proceso?

Un programa es un conjunto de instrucciones guardadas. Un proceso es ese programa cuando está en ejecución y el sistema operativo lo administra.

ProgramaEstá almacenado. Aún no está corriendo.
ProcesoPrograma en ejecución con memoria, estado e identificador.
CPUEjecuta las instrucciones de los procesos.
flowchart LR A[Programa] --> B[Se inicia] B --> C[Proceso] C --> D[Cola de listos] D --> E[CPU] E --> F[Termina]
Ejemplo cotidiano: abrir el navegador crea procesos que el sistema operativo debe identificar, organizar y ejecutar.

2. PID, PCB y estados

El PID es un identificador único. El PCB representa la información que el sistema guarda para administrar cada proceso: PID, estado, prioridad y otros datos.

flowchart LR N["Nuevo"] --> L["Listo"] L --> E["Ejecutando"] E -->|termina| T["Terminado"] E -->|pierde turno| L E -->|espera E/S| B["Bloqueado"] B -->|fin E/S| L
ListoQuiere CPU, pero todavía espera su turno.
BloqueadoNo puede seguir hasta que ocurra algo, por ejemplo terminar una lectura.

3. Procesos padre, hijo y huérfanos

Un proceso puede crear otros procesos. El que crea es el padre y el creado es el hijo. Si el padre termina pero el hijo continúa, el hijo queda huérfano. También existen escenarios de terminación en cascada.

flowchart TD P[Proceso padre] --> H1[Hijo 1] P --> H2[Hijo 2] H1 --> N[Nieto] P -. termina .-> O[Hijo puede continuar] P -. cascada .-> X[Hijos también terminan]

4. ¿Por qué planificar?

Cuando varios procesos están listos, el sistema operativo necesita decidir quién usa la CPU. Esa decisión la realiza el planificador.

flowchart LR Q[Procesos listos] --> S[Planificador] S --> CPU[CPU] CPU -->|termina| F[Finalizado] CPU -->|sale temporalmente| Q
No apropiativaEl proceso conserva la CPU hasta terminar o bloquearse.
ApropiativaEl sistema puede interrumpirlo y darle la CPU a otro proceso.

5. Métricas y conceptos

ConceptoExplicación sencilla
LlegadaMomento en que el proceso entra al sistema.
RáfagaTiempo de CPU que necesita.
EsperaTiempo que permanece esperando CPU.
RetornoTiempo desde que llega hasta que termina.
RespuestaTiempo hasta recibir CPU por primera vez.
QuantumTurno máximo usado en Round Robin.
InaniciónUn proceso espera demasiado porque otros siempre pasan primero.
Envejecimiento (aging)Su prioridad puede aumentar con el tiempo para darle oportunidad.

6. El objeto Proceso que usaremos

Todos los algoritmos reutilizan un objeto sencillo. Esto hace que el estudiante se concentre en la lógica.

Proceso.java
public class Proceso {
    String nombre;
    int llegada;
    int rafaga;
    int prioridad;
    int restante;

    public Proceso(String nombre, int llegada, int rafaga, int prioridad) {
        this.nombre = nombre;
        this.llegada = llegada;
        this.rafaga = rafaga;
        this.prioridad = prioridad;
        this.restante = rafaga;
    }
}
proceso.py
class Proceso:

Qué significa this.nombre = nombre: el dato recibido por el constructor se guarda dentro del objeto actual.

7. FCFS — First Come, First Served

El primero que llega es el primero que se atiende. Es parecido a una fila.

P1
0–4P2
4–7P3
7–9P4
9–10
FCFS.java
public class FCFS {
    public static void main(String[] args) {
        Proceso[] procesos = {
            new Proceso("P1", 0, 4, 1),
            new Proceso("P2", 1, 3, 1),
            new Proceso("P3", 2, 2, 1)
        };

        for (Proceso p : procesos) {
            System.out.println("Ejecutando " + p.nombre);
            System.out.println("Duracion: " + p.rafaga);
        }
    }
}
fcfs.py

8. SJF — Shortest Job First

Entre los procesos disponibles, se ejecuta primero el que tenga la ráfaga más corta.

flowchart LR A[P1 = 8] --> D[Orden] B[P2 = 4] --> D C[P3 = 1] --> D D --> E[P3] E --> F[P2] F --> G[P1]
SJF.java
public class SJF {
    public static void main(String[] args) {
        Proceso[] p = {
            new Proceso("P1", 0, 8, 1),
            new Proceso("P2", 0, 4, 1),
            new Proceso("P3", 0, 1, 1)
        };

        for (int i = 0; i < p.length; i++) {
            for (int j = i + 1; j < p.length; j++) {
                if (p[j].rafaga < p[i].rafaga) {
                    Proceso aux = p[i];
                    p[i] = p[j];
                    p[j] = aux;
                }
            }
        }

        for (Proceso proceso : p) {
            System.out.println(proceso.nombre + " -> " + proceso.rafaga);
        }
    }
}
sjf.py

    Proceso("P1", 0, 8, 1),
    Proceso("P2", 0, 4, 1),
    Proceso("P3", 0, 1, 1)
]

            auxiliar = procesos[i]

Este ejemplo es SJF no apropiativo y simplificado: suponemos que los procesos ya están disponibles.

9. SJFT / SRTF — Menor tiempo restante

SJFT se trabaja aquí como la versión apropiativa de SJF, conocida normalmente como SRTF (Shortest Remaining Time First). En cada unidad de tiempo se revisan los procesos que ya llegaron y se ejecuta el que tenga el menor tiempo restante.

flowchart LR A["t = 0 · P1 restante 7"] --> B["Ejecuta P1"] B --> C["t = 2 · llega P2 restante 4"] C --> D{"¿Quién tiene menor restante?"} D -->|P2| E["CPU cambia a P2"] E --> F["t = 4 · llega P3 restante 1"] F --> G["CPU cambia a P3"] G --> H["P3 termina"] H --> I["Se vuelve a comparar P1 y P2"]
Idea para recordar: SJF elige el trabajo más corto y lo deja terminar; SJFT/SRTF puede interrumpir el proceso actual si llega otro con menor tiempo restante.
SJFT.java
public class SJFT {
    public static void main(String[] args) {
        Proceso[] procesos = {
            new Proceso("P1", 0, 7, 2),
            new Proceso("P2", 2, 4, 1),
            new Proceso("P3", 4, 1, 3)
        };

        int tiempo = 0;
        int terminados = 0;

        while (terminados < procesos.length) {
            Proceso mejor = null;

            for (Proceso proceso : procesos) {
                if (proceso.llegada <= tiempo && proceso.restante > 0) {
                    if (mejor == null || proceso.restante < mejor.restante) {
                        mejor = proceso;
                    }
                }
            }

            if (mejor == null) {
                tiempo++;
            } else {
                System.out.println("Tiempo " + tiempo +
                        ": ejecuta " + mejor.nombre);

                mejor.restante--;
                tiempo++;

                if (mejor.restante == 0) {
                    terminados++;
                    System.out.println(mejor.nombre + " termino");
                }
            }
        }
    }
}
sjft.py

    Proceso("P1", 0, 7, 2),
    Proceso("P2", 2, 4, 1),
    Proceso("P3", 4, 1, 3)
]

        tiempo += 1

            terminados += 1
            print(mejor.nombre, "termino")
Prueba: agrega un P4 que llegue en el tiempo 3 con ráfaga 2. Revisa si desplaza al proceso que esté usando la CPU.

10. Planificación por prioridad

Cada proceso tiene una prioridad. Para este taller, 1 significa mayor prioridad.

Prioridad.java
public class Prioridad {
    public static void main(String[] args) {
        Proceso[] p = {
            new Proceso("P1", 0, 3, 3),
            new Proceso("P2", 0, 2, 1),
            new Proceso("P3", 0, 4, 2)
        };

        for (int i = 0; i < p.length; i++) {
            for (int j = i + 1; j < p.length; j++) {
                if (p[j].prioridad < p[i].prioridad) {
                    Proceso aux = p[i];
                    p[i] = p[j];
                    p[j] = aux;
                }
            }
        }

        for (Proceso proceso : p) {
            System.out.println(proceso.nombre + " prioridad " + proceso.prioridad);
        }
    }
}

11. Round Robin

Cada proceso recibe un turno llamado quantum. Si no termina, vuelve al final de la cola.

flowchart LR P1[P1] --> P2[P2] --> P3[P3] --> P1
RoundRobin.java
public class RoundRobin {
    public static void main(String[] args) {
        Proceso[] p = {
            new Proceso("P1", 0, 5, 1),
            new Proceso("P2", 0, 4, 1),
            new Proceso("P3", 0, 3, 1)
        };

        int quantum = 2;
        boolean quedan = true;

        while (quedan) {
            quedan = false;

            for (Proceso proceso : p) {
                if (proceso.rafaga > 0) {
                    quedan = true;

                    if (proceso.rafaga <= quantum) {
                        System.out.println(proceso.nombre + " termina");
                        proceso.rafaga = 0;
                    } else {
                        System.out.println(proceso.nombre + " usa " + quantum);
                        proceso.rafaga = proceso.rafaga - quantum;
                    }
                }
            }
        }
    }
}
round_robin.py
procesos = [
    Proceso("P1", 0, 5, 1),
    Proceso("P2", 0, 4, 1),
    Proceso("P3", 0, 3, 1)
]

quantum = 2

    for p in procesos:

            quedan = True

            if p.rafaga <= quantum:
                print(p.nombre, "termina")
                p.rafaga = 0
            else:
                print(p.nombre, "usa", quantum)
                p.rafaga = p.rafaga - quantum

12. Colas multinivel

No todos los procesos tienen que esperar en la misma cola. Podemos separar, por ejemplo, tareas interactivas y tareas de fondo.

flowchart TD A[Procesos] --> H[Cola alta] A --> M[Cola media] A --> B[Cola baja] H --> CPU[CPU] M --> CPU B --> CPU
ColasMultinivel.java
public class ColasMultinivel {
    public static void main(String[] args) {
        Proceso[] alta = {
            new Proceso("Editor", 0, 2, 1),
            new Proceso("Navegador", 0, 3, 1)
        };

        Proceso[] baja = {
            new Proceso("Copia", 0, 5, 3),
            new Proceso("Actualizacion", 0, 4, 3)
        };

        System.out.println("COLA ALTA");
        for (Proceso p : alta) {
            System.out.println("Ejecutando " + p.nombre);
        }

        System.out.println("COLA BAJA");
        for (Proceso p : baja) {
            System.out.println("Ejecutando " + p.nombre);
        }
    }
}
colas_multinivel.py

13. MLFQ básico

En las colas multinivel con realimentación, un proceso puede cambiar de cola según su comportamiento.

flowchart TD A[Cola alta] -->|usa todo el quantum| B[Cola media] B -->|usa todo el quantum| C[Cola baja] C -->|espera demasiado / aging| B B -->|espera demasiado| A
Para mantener el código apto para principiantes, aquí nos concentramos en la idea: procesos que consumen mucho CPU pueden bajar de cola; procesos que esperan demasiado pueden subir.
