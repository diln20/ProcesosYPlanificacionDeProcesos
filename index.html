Procesos y planificación de procesos

Un taller para estudiantes que están empezando. Se trabaja con sintaxis sencilla, ejemplos visuales y el mismo objeto Proceso en Java y Python para entender qué hace cada algoritmo sin distraerse con estructuras avanzadas.

1. Repaso: ¿qué es un proceso?

Un programa es un conjunto de instrucciones guardadas. Un proceso es ese programa cuando está en ejecución y el sistema operativo lo administra.

ProgramaEstá almacenado. Aún no está corriendo.
ProcesoPrograma en ejecución con memoria, estado e identificador.
CPUEjecuta las instrucciones de los procesos.
flowchart LR A[Programa] --> B[Se inicia] B --> C[Proceso] C --> D[Cola de listos] D --> E[CPU] E --> F[Termina]
Ejemplo cotidiano: abrir el navegador crea procesos que el sistema operativo debe identificar, organizar y ejecutar.

2. PID, PCB y estados

El PID es un identificador único. El PCB representa la información que el sistema guarda para administrar cada proceso: PID, estado, prioridad y otros datos.

flowchart LR N["Nuevo"] --> L["Listo"] L --> E["Ejecutando"] E -->|termina| T["Terminado"] E -->|pierde turno| L E -->|espera E/S| B["Bloqueado"] B -->|fin E/S| L
ListoQuiere CPU, pero todavía espera su turno.
BloqueadoNo puede seguir hasta que ocurra algo, por ejemplo terminar una lectura.

3. Procesos padre, hijo y huérfanos

Un proceso puede crear otros procesos. El que crea es el padre y el creado es el hijo. Si el padre termina pero el hijo continúa, el hijo queda huérfano. También existen escenarios de terminación en cascada.

flowchart TD P[Proceso padre] --> H1[Hijo 1] P --> H2[Hijo 2] H1 --> N[Nieto] P -. termina .-> O[Hijo puede continuar] P -. cascada .-> X[Hijos también terminan]

4. ¿Por qué planificar?

Cuando varios procesos están listos, el sistema operativo necesita decidir quién usa la CPU. Esa decisión la realiza el planificador.

flowchart LR Q[Procesos listos] --> S[Planificador] S --> CPU[CPU] CPU -->|termina| F[Finalizado] CPU -->|sale temporalmente| Q
No apropiativaEl proceso conserva la CPU hasta terminar o bloquearse.
ApropiativaEl sistema puede interrumpirlo y darle la CPU a otro proceso.

5. Métricas y conceptos

ConceptoExplicación sencilla
LlegadaMomento en que el proceso entra al sistema.
RáfagaTiempo de CPU que necesita.
EsperaTiempo que permanece esperando CPU.
RetornoTiempo desde que llega hasta que termina.
RespuestaTiempo hasta recibir CPU por primera vez.
QuantumTurno máximo usado en Round Robin.
InaniciónUn proceso espera demasiado porque otros siempre pasan primero.
Envejecimiento (aging)Su prioridad puede aumentar con el tiempo para darle oportunidad.

6. El objeto Proceso que usaremos

Todos los algoritmos reutilizan un objeto sencillo. Esto hace que el estudiante se concentre en la lógica.

Proceso.java
public class Proceso {

    // Guarda el nombre de la tarea
    String nombre;

    // Guarda el momento en que llega la tarea
    int llegada;

    // Guarda cuanto tiempo necesita la tarea
    int rafaga;

    // Guarda la prioridad de la tarea
    int prioridad;

    // Guarda cuanto tiempo le falta por terminar
    int restante;

    public Proceso(String nombre, int llegada, int rafaga, int prioridad) {

        // Guardamos el nombre que recibimos
        this.nombre = nombre;

        // Guardamos el tiempo de llegada
        this.llegada = llegada;

        // Guardamos la duracion total
        this.rafaga = rafaga;

        // Guardamos la prioridad
        this.prioridad = prioridad;

        // Al inicio falta toda la rafaga por ejecutar
        this.restante = rafaga;
    }
}

7. FCFS — First Come, First Served

El primero que llega es el primero que se atiende. Es parecido a una fila.

Situacion de la vida real: una fila en una panaderiaAna llega primero, luego Luis y despues Sara. Se atiende a Ana, luego a Luis y al final a Sara. Eso es FCFS / FIFO.
Ana
0-4Luis
4-7Sara
7-9Pedro
9-10
FCFS.java
public class FCFS {

    public static void main(String[] args) {

        // Cada objeto representa una persona en una fila
        Proceso[] lista = {
            new Proceso("Ana", 0, 4, 1),
            new Proceso("Luis", 1, 3, 1),
            new Proceso("Sara", 2, 2, 1)
        };

        // Recorremos la fila desde la primera posicion
        for (int i = 0; i < lista.length; i++) {

            // Tomamos la persona de la posicion i
            Proceso persona = lista[i];

            // Mostramos quien esta siendo atendido
            System.out.println("Atendiendo a: " + persona.nombre);

            // Mostramos cuanto tarda su turno
            System.out.println("Tiempo: " + persona.rafaga);
        }
    }
}

8. SJF — Shortest Job First

Entre los procesos disponibles, se ejecuta primero el que tenga la rafaga mas corta.

Situacion de la vida real: tareas de la casaTienes que guardar un cuaderno, lavar un plato y ordenar toda la habitacion. Primero haces la tarea mas corta. Esa es la idea de SJF.
flowchart LR A["Ordenar habitacion = 8"] --> D["Comparar tiempos"] B["Lavar plato = 4"] --> D C["Guardar cuaderno = 1"] --> D D --> E["Guardar cuaderno"] E --> F["Lavar plato"] F --> G["Ordenar habitacion"]
SJF.java
public class SJF {

    public static void main(String[] args) {

        // Creamos tres tareas de la casa
        Proceso[] lista = {
            new Proceso("Ordenar habitacion", 0, 8, 1),
            new Proceso("Lavar plato", 0, 4, 1),
            new Proceso("Guardar cuaderno", 0, 1, 1)
        };

        // Recorremos la lista desde la primera posicion
        for (int i = 0; i < lista.length; i++) {

            // Comparamos con las posiciones que estan despues
            for (int j = i + 1; j < lista.length; j++) {

                // Si la tarea j dura menos que la tarea i
                if (lista[j].rafaga < lista[i].rafaga) {

                    // Guardamos temporalmente la tarea i
                    Proceso auxiliar = lista[i];

                    // Ponemos la tarea corta en la posicion i
                    lista[i] = lista[j];

                    // Ponemos la otra tarea en la posicion j
                    lista[j] = auxiliar;
                }
            }
        }

        // Mostramos el orden final
        for (int i = 0; i < lista.length; i++) {
            System.out.println(lista[i].nombre);
        }
    }
}

9. SJFT — SJF con tiempo de llegada

En este taller usamos SJFT para practicar SJF teniendo en cuenta el tiempo de llegada. Solo se comparan los procesos que ya llegaron. Cuando se escoge uno, se deja terminar antes de elegir otro.

Situacion de la vida real: trabajos en una mesaA las 8:00 llega una tarea de 6 minutos. A las 8:02 llega una de 2 minutos. Cuando la primera termina, miras las tareas que ya llegaron y haces primero la mas corta.
flowchart LR A["Llega tarea larga - 6 min"] --> B["Empieza tarea larga"] B --> C["Llega tarea corta - 2 min"] C --> D["Termina tarea larga"] D --> E{"Que tareas esperan"} E --> F["Tarea corta es la menor"] F --> G["Ejecuta tarea corta"]
Idea clave: SJFT mira el tiempo de llegada, pero en este ejemplo no interrumpe al proceso que ya esta ejecutando.
SJFT.java
public class SJFT {
    public static void main(String[] args) {

        // Creamos procesos con llegada y rafaga
        Proceso[] lista = {
            new Proceso("Descargar archivo", 0, 6, 1),
            new Proceso("Tarea corta", 2, 2, 1),
            new Proceso("Tarea media", 3, 4, 1)
        };

        int tiempo = 0;
        int terminados = 0;

        while (terminados < lista.length) {

            // Aqui guardamos el proceso mas corto que ya llego
            Proceso mejor = null;

            // Recorremos la lista posicion por posicion
            for (int i = 0; i < lista.length; i++) {

                Proceso proceso = lista[i];

                // Solo miramos procesos que ya llegaron y no terminaron
                if (proceso.llegada <= tiempo && proceso.restante > 0) {

                    // Si no tenemos uno o este es mas corto, lo guardamos
                    if (mejor == null || proceso.rafaga < mejor.rafaga) {
                        mejor = proceso;
                    }
                }
            }

            // Si no ha llegado ningun proceso, avanza el tiempo
            if (mejor == null) {
                tiempo++;
            } else {

                System.out.println("Ejecuta: " + mejor.nombre);

                // En SJFT sencillo lo dejamos terminar completo
                tiempo = tiempo + mejor.rafaga;
                mejor.restante = 0;
                terminados++;
            }
        }
    }
}

10. SRTF — Shortest Remaining Time First

SRTF significa que siempre se ejecuta el proceso con menor tiempo restante. A diferencia de SJFT, aqui si puede interrumpirse el proceso actual cuando llega otro mas corto.

Ejemplo sencillo dentro de un sistema operativoEl computador esta ejecutando una tarea larga como Descargar archivo. Dos segundos despues el usuario abre la calculadora. Ese nuevo proceso entra a la cola de listos. SRTF compara lo que le falta a cada proceso y, si la calculadora necesita menos tiempo, la CPU la atiende primero.
Cola de listosAqui estan los procesos que ya llegaron y estan esperando CPU.
Planificador SRTFRevisa la cola y escoge el proceso con menor tiempo restante.
Importante: en un sistema operativo real no se usa Thread.sleep() de esta forma para planificar procesos. En este taller lo usamos solamente para simular el paso del tiempo y la llegada de un proceso nuevo. La idea que representa es: llega un proceso, entra a la cola de listos y el planificador vuelve a decidir.
flowchart LR A["CPU ejecuta Descargar archivo - faltan 7"] --> B["Despues del timeout llega Abrir calculadora - faltan 2"] B --> C{"Cual proceso tiene menor tiempo restante"} C --> D["Abrir calculadora toma la CPU"] D --> E["Abrir calculadora termina"] E --> F["Descargar archivo vuelve a la CPU"]
Idea clave: SRTF es apropiativo. Puede quitarle la CPU a un proceso si llega otro con menor tiempo restante.

Cuando termina esa espera, simula que el usuario abre la calculadora y crea el proceso Abrir calculadora. Ese proceso entra a la cola de listos. En la siguiente revision, SRTF compara los tiempos restantes y lo acomoda automaticamente.
Como leer este codigo
1. colaListos representa la cola de procesos listos del sistema operativo.
2. LlegadaProceso espera 2 segundos y despues agrega un proceso nuevo.
3. elegirMasCorto() representa al planificador SRTF.
4. Cada Thread.sleep(1000) representa una unidad de tiempo de la simulacion.
SRTF.java
import java.util.ArrayList;


// Esta clase simula que un nuevo proceso llega despues
class LlegadaProceso extends Thread {

    // Esta es la misma cola de listos que usa el planificador
    ArrayList<Proceso> colaListos;


    public LlegadaProceso(ArrayList<Proceso> colaListos) {

        // Guardamos la cola para poder agregar un proceso despues
        this.colaListos = colaListos;
    }


    public void run() {

        try {

            // Esperamos 2 segundos
            // Durante este tiempo otro proceso ya esta usando la CPU
            Thread.sleep(2000);

        } catch (Exception error) {

            System.out.println("Error en la espera");
        }


        // Despues del timeout simulamos que el usuario
        // abre la calculadora
        Proceso calculadora =
            new Proceso("Abrir calculadora", 2, 2, 1);


        // El nuevo proceso entra a la cola de listos
        synchronized (colaListos) {

            colaListos.add(calculadora);
        }


        System.out.println("");
        System.out.println(
            "Nuevo proceso en la cola: " + calculadora.nombre
        );
        System.out.println("");
    }
}



public class SRTF {


    // Este metodo representa al planificador
    // Busca el proceso con menor tiempo restante
    public static Proceso elegirMasCorto(
        ArrayList<Proceso> colaListos
    ) {

        Proceso mejor = null;


        // Recorremos la cola posicion por posicion
        for (int i = 0; i < colaListos.size(); i++) {

            // Tomamos el proceso de la posicion i
            Proceso proceso = colaListos.get(i);


            // Solo miramos procesos que no han terminado
            if (proceso.restante > 0) {


                // Si todavia no tenemos un proceso elegido
                if (mejor == null) {

                    mejor = proceso;

                } else {


                    // Si este proceso necesita menos tiempo
                    if (proceso.restante < mejor.restante) {

                        mejor = proceso;
                    }
                }
            }
        }


        // Devolvemos el proceso que debe usar la CPU
        return mejor;
    }



    public static void main(String[] args) {


        // Esta lista representa la cola de listos
        ArrayList<Proceso> colaListos =
            new ArrayList<Proceso>();


        // Al inicio solo existe una tarea larga
        Proceso descarga =
            new Proceso("Descargar archivo", 0, 7, 1);


        // La descarga entra a la cola de listos
        colaListos.add(descarga);


        // Creamos el hilo que simula una nueva llegada
        LlegadaProceso llegada =
            new LlegadaProceso(colaListos);


        // Empezamos a contar el timeout
        llegada.start();


        int tiempo = 0;


        while (true) {


            Proceso actual;


            // Protegemos la cola mientras el planificador la revisa
            synchronized (colaListos) {

                // El planificador escoge el proceso mas corto
                actual = elegirMasCorto(colaListos);
            }


            // Si hay un proceso para ejecutar
            if (actual != null) {


                System.out.println(
                    "Tiempo " + tiempo +
                    " -> CPU: " + actual.nombre +
                    " | restante: " + actual.restante
                );


                // Simulamos una unidad de trabajo de la CPU
                actual.restante--;


                // Si llego a cero, termino
                if (actual.restante == 0) {

                    System.out.println(
                        actual.nombre + " termino"
                    );
                }

            } else {


                // Si ya no viene otro proceso, terminamos la simulacion
                if (llegada.isAlive() == false) {

                    break;
                }


                System.out.println(
                    "Tiempo " + tiempo +
                    " -> CPU esperando"
                );
            }


            try {

                // Una unidad de tiempo dura un segundo
                Thread.sleep(1000);

            } catch (Exception error) {

                System.out.println("Error en la pausa");
            }


            // Avanzamos el reloj de la simulacion
            tiempo++;
        }


        System.out.println("Todos los procesos terminaron");
    }
}
Relacion con el sistema operativo: colaListos representa la cola de listos, elegirMasCorto() representa la decision del planificador y el hilo LlegadaProceso representa un evento externo que hace aparecer un proceso nuevo. Es una simulacion educativa, no el codigo real de Windows, Linux o Android.

11. Planificacion por prioridad

Cada proceso tiene una prioridad. Para este taller, 1 significa mayor prioridad.

Situacion de la vida real: una clinicaUna emergencia se atiende antes que un control normal. La tarea mas importante pasa primero. Esa es la idea de prioridad.
Prioridad.java
public class Prioridad {

    public static void main(String[] args) {

        // Creamos tres personas que esperan atencion
        Proceso[] lista = {
            new Proceso("Control normal", 0, 3, 3),
            new Proceso("Emergencia", 0, 2, 1),
            new Proceso("Consulta rapida", 0, 4, 2)
        };

        // Recorremos la lista para ordenar por prioridad
        for (int i = 0; i < lista.length; i++) {

            for (int j = i + 1; j < lista.length; j++) {

                // El numero menor representa mayor prioridad
                if (lista[j].prioridad < lista[i].prioridad) {

                    // Guardamos un elemento temporal
                    Proceso auxiliar = lista[i];

                    // Intercambiamos las posiciones
                    lista[i] = lista[j];
                    lista[j] = auxiliar;
                }
            }
        }

        // Mostramos el orden de atencion
        for (int i = 0; i < lista.length; i++) {
            System.out.println(lista[i].nombre);
        }
    }
}

12. Round Robin

Cada proceso recibe un turno llamado quantum. Si no termina, vuelve al final de la cola.

Situacion de la vida real: turnos en un columpioTres ninos usan un solo columpio. Cada uno tiene 2 minutos. Cuando termina su turno, pasa el siguiente. Si quiere seguir, vuelve al final de la fila.
flowchart LR A["Ana"] --> L["Luis"] --> S["Sara"] --> A
RoundRobin.java
public class RoundRobin {

    public static void main(String[] args) {

        // Cada persona quiere usar el columpio
        Proceso[] lista = {
            new Proceso("Ana", 0, 5, 1),
            new Proceso("Luis", 0, 4, 1),
            new Proceso("Sara", 0, 3, 1)
        };

        // Cada turno dura dos minutos
        int quantum = 2;

        // Esta variable indica si alguien aun necesita turno
        boolean quedan = true;

        while (quedan) {

            // Al iniciar una vuelta asumimos que nadie queda
            quedan = false;

            // Recorremos la fila persona por persona
            for (int i = 0; i < lista.length; i++) {

                Proceso persona = lista[i];

                // Si aun le falta tiempo
                if (persona.restante > 0) {

                    quedan = true;

                    // Si puede terminar en este turno
                    if (persona.restante <= quantum) {

                        System.out.println(persona.nombre + " termina");

                        // Ya no le queda tiempo
                        persona.restante = 0;

                    } else {

                        System.out.println(persona.nombre + " usa " + quantum);

                        // Restamos el tiempo usado
                        persona.restante = persona.restante - quantum;
                    }
                }
            }
        }
    }
}

# Indica si alguien aun necesita turno
quedan = True

while quedan:

    # Al iniciar una vuelta asumimos que nadie queda
    quedan = False

    # Recorremos la fila persona por persona
    for i in range(len(lista)):

        persona = lista[i]

        # Si aun le falta tiempo
        if persona.restante > 0:

            quedan = True

            # Si puede terminar en este turno
            if persona.restante <= quantum:

                print(persona.nombre, "termina")
                persona.restante = 0

            else:

                print(persona.nombre, "usa", quantum)

                # Restamos el tiempo usado
                persona.restante -= quantum

13. Colas multinivel

En colas multinivel tenemos tres colas diferentes. Cada cola puede usar su propio algoritmo.

Cola alta → Round RobinPara tareas rapidas e interactivas. Ejemplo: responder mensajes o cambiar entre ventanas.
Cola media → SJFPara trabajos cortos. Ejemplo: imprimir una hoja o guardar un archivo pequeno.
Cola baja → FIFO / FCFSPara trabajos largos o menos urgentes. Ejemplo: copiar muchos archivos o hacer una copia de seguridad.
flowchart TD A["Procesos nuevos"] --> H["Cola alta - Round Robin"] A --> M["Cola media - SJF"] A --> B["Cola baja - FIFO / FCFS"] H --> CPU["CPU"] M --> CPU B --> CPU
Forma facil de recordarlo: alta = turnos, media = primero el corto, baja = orden de llegada.
ColasMultinivel.java
public class ColasMultinivel {

    // Cola alta usa Round Robin
    public static void roundRobin(Proceso[] lista, int quantum) {

        boolean quedan = true;

        while (quedan) {

            quedan = false;

            // Recorremos la lista posicion por posicion
            for (int i = 0; i < lista.length; i++) {

                Proceso proceso = lista[i];

                if (proceso.restante > 0) {

                    quedan = true;

                    // Si le queda poco, termina
                    if (proceso.restante <= quantum) {
                        proceso.restante = 0;
                    } else {
                        proceso.restante = proceso.restante - quantum;
                    }

                    System.out.println("Round Robin: " + proceso.nombre);
                }
            }
        }
    }

    // Cola media usa SJF
    public static void sjf(Proceso[] lista) {

        // Ordenamos de menor a mayor rafaga
        for (int i = 0; i < lista.length; i++) {

            for (int j = i + 1; j < lista.length; j++) {

                if (lista[j].rafaga < lista[i].rafaga) {

                    Proceso auxiliar = lista[i];
                    lista[i] = lista[j];
                    lista[j] = auxiliar;
                }
            }
        }

        // Ejecutamos en el nuevo orden
        for (int i = 0; i < lista.length; i++) {
            System.out.println("SJF: " + lista[i].nombre);
        }
    }

    // Cola baja usa FIFO
    public static void fifo(Proceso[] lista) {

        // Se ejecuta en el mismo orden de llegada
        for (int i = 0; i < lista.length; i++) {
            System.out.println("FIFO: " + lista[i].nombre);
        }
    }

    public static void main(String[] args) {

        // Tareas rapidas
        Proceso[] colaAlta = {
            new Proceso("Responder chat", 0, 3, 1),
            new Proceso("Cambiar ventana", 0, 2, 1)
        };

        // Tareas cortas
        Proceso[] colaMedia = {
            new Proceso("Imprimir hoja", 0, 2, 2),
            new Proceso("Guardar archivo", 0, 1, 2)
        };

        // Tareas largas
        Proceso[] colaBaja = {
            new Proceso("Copiar archivos", 0, 8, 3),
            new Proceso("Hacer backup", 0, 10, 3)
        };

        roundRobin(colaAlta, 2);
        sjf(colaMedia);
        fifo(colaBaja);
    }
}

14. MLFQ basico

En las colas multinivel con realimentacion, un proceso puede cambiar de cola segun su comportamiento.

Situacion de la vida real: tareas que cambian de filaUna tarea empieza en la fila rapida. Si tarda demasiado, baja a otra fila. Si una tarea lleva mucho tiempo esperando, puede subir otra vez.
flowchart TD A[Cola alta] -->|usa todo el quantum| B[Cola media] B -->|usa todo el quantum| C[Cola baja] C -->|espera demasiado / aging| B B -->|espera demasiado| A
Para mantener el código apto para principiantes, aquí nos concentramos en la idea: procesos que consumen mucho CPU pueden bajar de cola; procesos que esperan demasiado pueden subir.

15. Comparacion

AlgoritmoIdeaDetalle importante
FCFSOrden de llegadaMuy simple, pero un proceso largo puede retrasar a los demás.
SJFRáfaga más cortaReduce espera en ciertos escenarios, pero puede perjudicar trabajos largos.
SJFTSJF con tiempo de llegadaElige el mas corto entre los que ya llegaron y deja que termine.
SRTFMenor tiempo restanteEs apropiativo: puede interrumpir al proceso actual.
